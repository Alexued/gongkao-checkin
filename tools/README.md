# 真题库补陈怀安讲解 · 工具链

给 `app/src/main/assets/bank_peipei.json`（1175 道资料分析真题）逐题补 `anim` 分步讲解。
补上之后 App 里那道题就从「看解析」（摊开粉笔原文）自动变成「下一步讲解 1/N」——
**不用改任何 UI 代码**，`BankQuestionView.explainNext()` 是按每题自己的 `anim` 是否为空分流的。

## 为什么要重算，不能照抄原解析

原解析里的公式和算式在原文是图片，抽取时丢了，常见成这样：

> 代入公式，倍，与B项最接近。

所以每题的算式必须自己重算一遍。已经出现过一次「解析说 B 项最接近但没给数」的题，
自己算完是 3.23（选 B），而 4.23 正好掉进 C——这种坑只有重算才能写出来。

## 讲解写法

沿用精选 65 题（`bank.json`）的四步结构和口吻：

1. **定题型** —— 一句话点出这是什么题、要用哪个公式，顺带指出题干里最要命的那几个字
2. **拆算** —— 用陈怀安的招（截位直除、退位修正法分档、百化分、大大则大、区间判定、
   十字交叉、混合后居中……），能秒杀就别硬算
3. **定选项** —— 落到具体选项，`pick: true` 标在这一步
4. **坑** —— 讲清每个诱饵是怎么算出来的。这一步最值钱，学生错在哪比对在哪重要

`facts` 里放正文中要高亮的数字（必须在 `b` 里逐字出现，校验器会查）。
`kill` 放这一步排除掉的选项字母，界面上会划掉。

## 命令

```bash
# 1. 导出一批还没写的题
node tools/dump_batch.cjs --chapter "增长率" --limit 10
node tools/dump_batch.cjs --skill "两期比重" --limit 8 --matlen 600

# 2. 看单题全貌（核对材料里到底有没有需要的数）
node tools/show.cjs 3_1_e3h
node tools/show.cjs 3_1_e3h --full     # 不截断

# 3. 写 tools/patch_xxx.json，格式 { "题目id": [ {t,b,kill,pick,facts}, ... ] }

# 4. 校验（合并前必跑）
node tools/check_anim.cjs tools/patch_xxx.json

# 5. 合并进题库
node tools/apply_anim.cjs tools/patch_xxx.json
node tools/apply_anim.cjs tools/patch_xxx.json --force   # 覆盖已有的

# 6. 全库体检
node tools/check_anim.cjs        # 校验已写的全部
node tools/count_blocked.cjs     # 估算有多少题写不了
node tools/find_gaps.cjs         # 三类题库缺陷统计
```

`check_anim.cjs` 查这些（都是真踩过的）：每题恰好一步 `pick=true`；`kill` 不含正确答案、
只能是 ABCD；`facts` 必须在正文里出现（写过一次 facts 写了「11.7%」而正文只写了「占比」，
高亮落空，被它挡下来了）；`t`/`b` 非空且 `b` 不短于 15 字。

## 写不了的题

见 `skipped.json`。两类：

- **缺图或缺表**（38 题左右）——解析要求「定位柱形图/折线图/表1/表2」，材料是纯文字。
  当初抽取只滤了「定位统计表/图」，漏了这几种说法。
- **材料增速被抠空**（193 题左右）——材料里「同比增长。」后面全是空，基期类题做不了。

判据是**本题需要的那个数在材料里有没有**，跟材料别处缺不缺无关——
已写的题里好几道就是「材料有缺口但本题用不到」。粗筛下来大约 944 题（80.3%）可写。

遇到写不了的题：**不要硬写**。材料里没有的数字写进讲解就是编数字，比留着原解析更糟。
记进 `skipped.json` 对应分类，附一句为什么。
